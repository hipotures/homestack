HomeStack TUI: the design the mockups show (version 2, btop grammar)
=====================================================================

Draft for review. Nothing here is built yet. All names and addresses are
examples (the repository is public). Version 1 is in git history (c45db43).


1. One program for everything
-----------------------------

`homestack` with no command, in a terminal, opens one full-screen program for
the install, the everyday work and the uninstall. `homestack --help` prints
the help; when the output is not a terminal, plain `homestack` prints the
help as today. The CLI commands stay. The minimum size is 80 x 24.

Nothing leaves the TUI. Choosing an SSH key, "touch your security key", a PIN,
an unknown host key, progress and errors are all shown inside it (03).

It uses ratatui, as the current installer form does. It is text only and works
over SSH.


2. The border is the interface (as in btop)
-------------------------------------------

Every panel is a rounded box. Its controls sit in its border, not on extra
rows, so the inside holds only data. Each place in the border has one job, the
same in every panel:

  top left       name of the panel and its digit (¹workspaces), and the
                 filter: ┌Filter┐
  top right      how the panel shows its data: carousels ┌‹ node: all ›┐
                 (changed with ←→), toggles, and ┌New┐
  bottom left    actions on the selected row: └Ssh┘└sTop┘└Refresh┘…
                 They are grey while nothing is selected.
  bottom right   the counter: selected / total (1/12), or the step (3/5)
  right edge     the scrollbar when the content is longer than the panel:
                 ↑ under the top corner, █ thumb, ↓ above the bottom corner

The key of a control is its highlighted letter.
  - In the TUI that letter has the accent colour.
  - In these TXT files it is the upper-case letter: └resiZe┘ is z,
    └miGrate┘ is g, ┌Filter┐ is f.
  - A symbol in the label is its key: └info ↵┘ is Enter, └tick ␣┘ is Space,
    └next ⇥┘ is Tab, ‹ › is ←→.
  - Mouse clicks on a control do the same as its key.

┌Filter┐ opens in place: the border becomes the input ┌filter: lab▏───┐.
Enter keeps the filter; Esc clears it. There is no pop-up.

A box inside a panel (a sub-box) holds what belongs to that panel:
  - the details of the selected workspace (10);
  - an action (12–14);
  - "each node gets" next to the storage chooser (06).
A sub-box has a fixed width; the list takes the rest. On a narrow window it
splits the panel top and bottom instead (09b, 12).


3. Two screens
--------------

A. Install screen (02–08; 18 is the uninstall)
   It opens by itself when there is no client.toml. Later it opens only
   from Menu › Reconfigure or Menu › Uninstall.
   The steps are in the top border, the current one raised:
       ✓access ─ ✓check ─┌settings┐─ review ─ install
   The buttons of the step are in the bottom border.
   After └Open HomeStack ↵┘ the install screen is gone.

B. Main screen (09–17)
   It opens at every start once client.toml exists. Its panels:
     ²cluster      nodes, servers, Gold, certificate, clock; ┌Menu┐ and the
                   preset in its top border
     ¹workspaces   the list, the details sub-box, the actions
     ³storage      the workspace disks of each node, with bars
     ⁴log          what HomeStack did and is doing
   The digits 1–4 show and hide panels. They are not tabs: you can have all
   four, or only the list (16). When the cluster panel is hidden, ┌Menu┐ and
   the preset move to the first panel that is shown.
   0 brings back the standard view: every panel, every node, no filter.

   Presets (P, or ┌‹ Preset ›┐) are saved sets of panels, chosen in
   Menu › Options. "auto" shows what fits the window.


4. Actions happen in a sub-box, never on a new screen
-----------------------------------------------------

Ssh, start/stop, setup, refresh, resize, add key, migrate, destroy and new
open as a sub-box of the workspaces panel (ssh: see 8). The other panels stay.
The stages of an action are in the top border of its sub-box, the current
one raised:

    ┌form┐ ─ plan ─ run

  - The plan says exactly what will change, in the words of the CLI's question.
  - Nothing changes before Apply. Esc closes the sub-box.
  - For destroy the focus starts on cancel.
  - Once the work runs, Esc only hides the sub-box; the work goes on. ⁴log
    shows it, and the row in the list is marked ◐.

The only boxes over the screen are for things that stop everything:
  - the security key, PIN or host key (03);
  - the Menu (15), with Help and Options in it;
  - the quit question.


5. Window size: panels appear and disappear as a whole
------------------------------------------------------

  < 80 x 24         Only the "terminal too small" notice (01).

  80–119 x 24–35    ²cluster on two lines, plus ¹workspaces.
                    The details and actions split the list top and bottom.
                    ³storage and ⁴log are hidden; turning off ²cluster (2)
                    gives room to one of them (09, 12, 17).
                    The bottom border drops └select ↑↓┘ to fit the actions.

  120–159 x 36–44   All four panels. Details are a sub-box next to the list.
                    ⁴log shows under the install screen too (10, 13, 14).

  160+ x 45+        The same panels, with more in each: CPU*/RAM* per node,
                    Root/Home/Free columns, a storage table, a taller log (11).

  - Width and height count separately. A panel shows when the user has it on
    AND it fits, in this order: workspaces, cluster, storage, log.
  - Nothing wraps. Text that does not fit is cut with "…".
  - Columns drop from the right, least important first.
  - The screen never shrinks to a small square in the middle of the window.


6. Colours (TXT cannot show them)
---------------------------------

  - Borders are grey; panel names are bold; the key letters are the accent
    colour.
  - Raised items (┌settings┐, ┌form┐) are bright; grey controls are dim.
  - The selected row (▶ in TXT) is inverse.
  - ● running / online and ✓ are green; ○ stopped is grey; ! is yellow;
    ✗ is red; ◐ (running work) is cyan.
  - Bars go green → yellow → red as the disk fills.
  - What is behind the Menu or the security-key box is dimmed.
  - * marks data the server does not send today.

8. Decisions (owner, 2026-10-14)
--------------------------------

  - Command: plain `homestack` opens the TUI.
  - Minimum size: 80 x 24.
  - Node CPU and RAM (11, marked *): decided after the TUI is built.
  - Start/stop and ssh into a workspace: yes. └sTart┘ / └sTop┘ (t) follows
    the state of the selected row; └Ssh┘ is s, so resize is └resiZe┘ (z).
    Start/stop needs new server operations (hs-core already has the Proxmox
    calls). How ssh runs (TUI suspended, a terminal in a panel, or a new
    window or Herdr pane) is decided after the TUI is built.

  uninstall                  Menu › Uninstall (18)
  discover                   Menu › Check this desktop (25)
  transport                  Menu › Check the servers (26)
  status                     main screen (09–11)
  status VMID|NAME           details sub-box of the selected row (09b, 10)
  create                     ┌New┐ (12)
  refresh                    └Refresh┘ (14)
  resize                     └resiZe┘ (19)
  addkey                     └addKey┘ (20)
  migrate                    └miGrate┘ (21)
  destroy                    └Destroy┘ (13)
  start, stop (new)          └sTart┘ / └sTop┘ (22)
  ssh (new)                  └Ssh┘; how it runs is decided later
  setup VMID [selectors]     └sEtup┘ (23)
  setup list                 the items in └sEtup┘ (the catalog)
  setup status VMID          the STATE column in └sEtup┘

  repo VMID [OWNER/REPO]     └sEtup┘ › Repositories (24)
  --json, -y                 CLI only; the TUI always shows the plan
